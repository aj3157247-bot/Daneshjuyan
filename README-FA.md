# دانشجویان — پلتفرم آموزشی دانشگاهی

نسخه یکپارچه پروژه با رابط فارسی/دری و راست‌به‌چپ، مناسب موبایل، بر پایه Cloudflare Pages Functions و D1. این پروژه شامل صفحه‌ها و گروه‌های رمزدار، نوت‌های مستقل برای ۸ سمستر، گروه عمومی دانشجویان، آپلود فایل و عکس با R2 و پنل مدیر اصلی است.

## قابلیت‌ها
- ساخت و جستجوی صفحه درسی و گروه گفتگوی اختصاصی.
- دسترسی به صفحه/گروه با رمز؛ رمز به صورت PBKDF2 هش‌شده ذخیره می‌شود و نشست صفحه در کوکی HttpOnly قرار می‌گیرد.
- ۸ سمستر مستقل در صفحه درسی؛ نوت‌ها، فایل‌ها و عکس‌های هر سمستر جدا نگهداری می‌شوند.
- نوت با عنوان و متن، چسباندن متن از موبایل و دکمه کپی.
- آپلود PDF، Word، PowerPoint و TXT؛ عکس JPG، PNG و WEBP؛ حداکثر ۱۵ مگابایت برای هر فایل.
- گروه عمومی دانشجویان با امکان مخفی‌کردن یا حذف پیام توسط مدیر اصلی.
- پنل مدیریت با شمارنده صفحه‌ها، گروه‌ها، نوت‌ها، فایل‌ها، عکس‌ها، پیام‌های عمومی، آمار بازدید ۱۴ روزه و مدیریت/حذف صفحه‌ها و گروه‌ها.
- ثبت بازدید صفحه‌ها برای آمار داخلی؛ شناسه تصادفی مرورگر در localStorage نگهداری می‌شود.

## راه‌اندازی Cloudflare Pages

1. پوشه‌های `functions/` و `public/` و فایل `schema.sql` را در مخزن GitHub پروژه قرار بده. Build output directory باید `public` باشد. Build command لازم نیست.
2. در Cloudflare D1 دیتابیس با نام `daneshjuyan` بساز یا از دیتابیس موجود استفاده کن. Binding باید `DB` باشد و به دیتابیس درست اشاره کند.
3. در D1 Console فایل کامل `schema.sql` را اجرا کن. اجرای مجدد آن برای جدول‌ها امن است. جدول‌های تازه شامل نوت سمستری، فایل‌ها، عکس‌ها، پیام عمومی و رویدادهای بازدید است.
4. در Cloudflare R2 یک bucket با نام `daneshjuyan-files` بساز. سپس در Pages → Settings → Functions، R2 binding با نام دقیق `FILES` را به آن وصل کن. تا زمانی که این binding وجود نداشته باشد، آپلود فایل و عکس کار نمی‌کند.
5. در Pages → Settings → Variables and Secrets، این مقادیر را برای Production و در صورت نیاز Preview تنظیم کن:
   - `SESSION_SECRET`: رشته تصادفی طولانی برای نشست صفحه‌ها.
   - `YAR_OWNER_EMAIL`: ایمیل مدیر اصلی (برای حساب فعلی: `abdullahjafari712@gmail.com`).
   - `YAR_ADMIN_PASSWORD`: رمز قوی و اختصاصی پنل مدیریت.
   - `YAR_ADMIN_SESSION_SECRET`: رشته تصادفی جداگانه و طولانی برای امضای نشست مدیر.
   مقادیر واقعی را داخل GitHub، فایل‌های عمومی یا کد قرار نده.
6. Deploy کن و `/api/health` را باز کن. `databaseStatus` باید `connected` و `schemaStatus` باید `ready` باشد و `storageConfigured` برای آپلود باید `true` شود.
7. از دکمه «مدیریت» در بالای سایت وارد پنل مدیر شو. ورود با `YAR_OWNER_EMAIL` و `YAR_ADMIN_PASSWORD` انجام می‌شود.

## نکات مهم
- این نسخه هنوز حساب کاربری دانشجو، تأیید هویت دانشگاهی و عضویت تأییدشده ندارد؛ فعلاً فضاهای اختصاصی با رمز محافظت می‌شوند و گروه عمومی نام نمایشی دارد. بنابراین برای انتشار عمومی در مقیاس بزرگ، پیش از هر چیز باید ثبت‌نام امن، محدودسازی نرخ پیام/آپلود، گزارش تخلف، سیاست حریم خصوصی و آزمون امنیتی اضافه شود.
- آمار بازدید از زمان Deploy نسخه دارای endpoint `/api/track` جمع می‌شود؛ آمار گذشته را نمی‌تواند به عقب برگرداند. این آمار داخلی است و با گزارش کامل Cloudflare Analytics یکی نیست.
- اجرای `schema.sql` روی دیتابیس موجود جدول‌های جدید را اضافه می‌کند؛ جدول‌ها و داده‌های قبلی حذف نمی‌شوند.
- اگر D1 یا R2 را به پروژه وصل نکرده باشی، ظاهر سایت بالا می‌آید ولی عملیات وابسته به آن سرویس کار نمی‌کند.
- `server.js` برای اجرای محلی Node است؛ APIهای Cloudflare Pages از فایل‌های `functions/api/` اجرا می‌شوند.
