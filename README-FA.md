# دانشجویان — نسخه حرفه‌ای پایه برای Cloudflare Pages

## آنچه این نسخه انجام می‌دهد
- صفحه اصلی خلوت با دو فهرست جدا: «صفحه‌ها» و «گروه‌ها».
- سازنده نام مورد، نام پوهنتون/دانشگاه، رشته، سمستر و نوبت را خودش وارد می‌کند؛ نام دانشگاه‌ها از قبل ثابت نشده است.
- همه می‌توانند کارت‌های معرفی را ببینند؛ محتوای خصوصی فقط بعد از وارد کردن رمز درست باز می‌شود.
- رمز در D1 با PBKDF2 هش‌شده ذخیره می‌شود. پس از ورود، کوکی HttpOnly/Secure/SameSite با اعتبار ۳۰ روزه همان صفحه/گروه را به خاطر می‌سپارد.
- نوت‌ها و پیام‌های گروه پس از ورود در D1 ذخیره می‌شوند؛ نوت‌ها قابلیت کپی دارند.
- بخش فایل‌ها در UI مشخص است اما اتصال R2 و آپلود فایل هنوز در این نسخه پیاده‌سازی نشده است. گالری عکس‌های یادگاری، مدیریت مالک/ادمین، بازیابی رمز، لایک/نظر و چت زنده (real-time) نیز هنوز نیازمند توسعه‌اند.

## انتشار در Cloudflare Pages از طریق GitHub
1. دانلود و از حالت ZIP خارج کن. محتوای پوشه `Daneshjuyan-main` را در ریشه همان مخزن GitHub جایگزین کن؛ پوشه‌های `public` و `functions` و فایل‌های `schema.sql` و `wrangler.toml` باید در ریشه مخزن باشند. `server.js` برای Pages لازم نیست، ولی فعلاً حذفش نکن.
2. Cloudflare Dashboard → Workers & Pages → پروژه Pages موجود → Settings → Builds & deployments: Build command را خالی بگذار و Build output directory را `public` قرار بده. اگر از GitHub متصل است، push جدید خودکار deploy می‌شود.
3. در Cloudflare پروژه → Settings → Functions → D1 database bindings یک binding با نام دقیق `DB` بساز و D1 database را انتخاب کن.
4. در D1 → دیتابیس → Console، محتوای کامل `schema.sql` را اجرا کن. این فایل شامل جداول پروژه قبلی و جداول جدید است.
5. در پروژه Pages → Settings → Variables and Secrets، یک Secret با نام `SESSION_SECRET` بساز و مقدار تصادفی طولانی (حداقل ۳۲ کاراکتر) بگذار. خود مقدار را در چت یا GitHub ننویس.
6. دوباره deploy کن. سپس `https://daneshjuyan.pages.dev/api/health` را باز کن. باید `databaseStatus: connected` و `schemaStatus: ready` و `sessionSecretConfigured: true` ببینی.
7. تست: یک صفحه آزمایشی بساز، خارج شو، با رمز درست وارد شو، یک نوت و پیام بفرست، صفحه را refresh کن و بررسی کن نوت/پیام باقی مانده باشند. با رمز اشتباه هم باید ورود رد شود.

## نکات مهم
- چون سایت فعلی به GitHub وصل است، نیازی به ساخت Pages project تازه نیست.
- اگر `schema.sql` را روی دیتابیس موجود اجرا می‌کنی، `CREATE TABLE IF NOT EXISTS` جداول موجود را حذف نمی‌کند. قبل از تغییرات بزرگ از دیتابیس backup بگیر.
- فهرست عمومی صفحه‌ها نام/پوهنتون/رشته/سمستر را نشان می‌دهد، نه محتوای خصوصی.
- در این نسخه هرکس رمز را بداند می‌تواند عضو فضای خصوصی شود. سازوکار مالکیت سازنده، تغییر رمز و مدیریت اعضا هنوز پیاده نشده است؛ برای استفاده گسترده واقعی باید اضافه شود.
- آپلود فایل، عکس‌های یادگاری، مدیریت گزارش‌ها و پنل ادمین کامل در این نسخه آماده نیستند؛ ادعای تکمیل آن‌ها درست نخواهد بود.
